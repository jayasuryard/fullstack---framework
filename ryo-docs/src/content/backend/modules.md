# Modules

The backend is modular: one folder per domain under `backend/modules/`. The framework ships exactly **one** domain module — `auth`. Your product's modules (invoice, course, project, ...) are generated by script, never hand-forked.

## Module Anatomy

```
modules/<name>/
├── routes/
│   └── <name>Routes.js      # router + middleware chain + zod schemas
└── services/
    └── <Name>Service.js     # business logic, Prisma/Redis/queue calls
```

Other conventions:

- Mount in `backend/routes/index.js` under `/api/v1/<actor>/<resource>` (e.g. `/api/v1/admin/invoices`). `gen:module` wires this automatically.
- Services never touch `req`/`res`; they accept plain data and return plain data (or throw `response()` errors handled by routes).
- Each module owns its routes, services, and schemas. Shared infrastructure (envelope, pagination, queue, WS) stays in `backend/helpers/`.

## The auth Module

| File | Responsibility |
|------|----------------|
| `routes/authRoutes.js` | endpoint map + zod schemas (`loginSchema`, `refreshSchema`, `forgotSchema`, `resetSchema`) |
| `services/AuthService.js` | login, refresh rotation, logout, me, profile update, OTP reset, lockout logic |

See [Authentication](./authentication) for behavior.

## Module Creation Loop

```bash
# 1. scaffold
npm run gen:module invoice
#    creates modules/invoice/{routes,services}/ + mounts route in routes/index.js

# 2. Prisma model (validated, above the marker)
npm run gen:model Invoice id:cuid name:String amount:Float createdAt:DateTime

# 3. migration
npm run gen:migration add_invoice

# 4. service logic — modules/invoice/services/InvoiceService.js
# 5. routes — modules/invoice/routes/invoiceRoutes.js (chain verifyToken/role/accessLevel/validateBody)
# 6. frontend namespace — frontend/src/server/api.js
# 7. page — frontend/src/pages/invoice/InvoicePage.jsx
# 8. route — frontend/src/App.jsx
# 9. Postman collection
npm run gen:postman "My App API"
```

## Route File Shape

```js
import { Router } from 'express'
import { verifyToken } from '../../../middleware/verifyToken.js'
import { role } from '../../../middleware/role.js'
import { requireReadWrite } from '../../../middleware/accessLevel.js'
import { validateBody } from '../../../middleware/validate.js'
import { InvoiceService } from '../services/InvoiceService.js'

const router = Router()
const listSchema = z.object({ page: z.coerce.number().min(1).default(1), limit: z.coerce.number().min(1).max(100).default(10) })

router.get('/',    verifyToken, role('admin'), validateBody(listSchema), InvoiceService.list)
router.post('/',   verifyToken, role('admin'), requireReadWrite(), validateBody(createSchema), InvoiceService.create)

export default router
```

## Adding Cross-Cutting Helpers

New helpers go in `backend/helpers/` (e.g. `helpers/pdf.js`). If every module needs them, export from the shared area; if one module needs them, keep them inside the module.

## What Not to Do

- Do not create top-level route folders outside `modules/` for domain resources.
- Do not put Prisma queries in route files.
- Do not reuse the auth module for your domain logic.
